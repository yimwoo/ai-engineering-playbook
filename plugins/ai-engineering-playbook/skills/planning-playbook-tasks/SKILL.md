# Planning Playbook Tasks

## Workflow
1. Read the objective and the durable source-of-truth docs.
2. Decide whether the work is a task, phase, or design-change package.
3. Name the files or modules likely to change.
4. Define acceptance criteria and verification before implementation starts.
5. Record assumptions, risks, dependencies, and the required handoff shape.

## Task Packet Contract
Every implementation task should include:
- objective
- scope
- context to read
- files likely to change
- verification command
- acceptance criteria
- out-of-scope items
- handoff expectation
