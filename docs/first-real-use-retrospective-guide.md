# First Real-Use Retrospective Guide

## Purpose
Use this guide after you apply the playbook to one real software task, feature, or milestone.

The goal is not to produce a long report.
The goal is to learn what parts of the playbook actually helped and what parts felt heavy.

---

## What to review
Pick one real piece of work, for example:
- implementing a bounded feature
- planning a milestone
- using Claude Code and Codex on the same task
- making a design-sensitive change
- rescuing a messy area of an existing repo

---

## The 7 reflection questions
1. What was the task?
2. Which docs or prompts did I actually use?
3. What helped the most?
4. What felt unnecessary or too heavy?
5. Did repo-based memory help when switching sessions or agents?
6. Did the code agent drift, over-ask, or take shortcuts?
7. What one thing should I change in my workflow next time?

## Recommendation
For the first few real uses, keep retros short.
The main purpose is to identify:
- what you actually use
- what is optional in practice
- what should be simplified
- what deserves to become a stable pattern
