# Status Update Protocol

## Purpose
Keep `status.md` useful as the bridge between sessions.

## Who Updates It
Preferred ownership:
- orchestrator agent after meaningful task completion or integration
- implementation agent for local task progress when no orchestrator is active
- human review when milestone meaning or risk posture changes significantly

## Update Triggers
Update `status.md` when:
- a task packet is completed
- a meaningful blocker appears
- a major assumption changes
- a milestone changes
- a design-change package is approved
- architecture-relevant work changes next steps

## Minimum Update Fields
- completed recently
- in progress
- next recommended tasks
- open blockers
- active assumptions
- risks
- notes for next session

## Rule
Do not let `status.md` become a diary. It should summarize the current operational state.
